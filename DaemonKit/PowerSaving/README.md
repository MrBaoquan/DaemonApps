# 节能窗口功能说明

## 功能概述

节能窗口是 DaemonKit 内置的一个显示器能源管理工具，允许用户在不同的显示器配置间快速切换，以实现省电目的。主要功能包括：

- **显示器发现**：自动扫描系统中所有连接的显示设备
- **亮度管理**：通过 DDC/CI 协议控制显示器亮度
- **省电模式**：一键切换到预设的低亮度配置
- **正常模式**：恢复到原始亮度设置
- **自定义配置**：为不同显示器设置独立的亮度目标

## 打开方式

1. 在 DaemonKit 主窗口中，点击菜单或工具栏中的"能源管理"或类似选项
2. 或使用快捷键/菜单项 `OpenPowerSavingPanel` 命令

## 用户界面说明

### 主要区域

#### 显示器列表
- 显示所有已连接的显示器及其当前状态
- 每个显示器卡片显示以下信息：
  - 🖥️ 显示器名称
  - 设备名称（如 DISPLAY1）
  - 连接状态指示（绿色勾号表示已连接）
  - 当前亮度百分比

#### 模式切换按钮
- **省电模式**：将所有显示器切换到低亮度配置（默认 40%）
- **正常模式**：恢复所有显示器到应用省电前的原始亮度

#### 默认省电亮度设置
- 滑块：调整省电模式的默认亮度值（0-100%）
- 此设置适用于所有未单独配置的显示器
- 实时同步到硬件（修改后立即生效）

#### 单显示器配置
对于每个显示器，可以进行以下操作：

1. **启用覆盖** - 复选框
   - 勾选后，该显示器可独立设置亮度
   - 取消勾选后，使用全局默认省电亮度

2. **亮度滑块** - 当覆盖启用时可用
   - 调整该显示器在省电模式下的目标亮度
   - 范围：0-100%

3. **应用按钮** - 立即应用所有自定义亮度配置

### 状态消息区域
- 显示当前操作的结果信息
- 格式：`操作名称，成功 X/Y`（X 为成功的显示器数量，Y 为总数）
- 示例：`已切换到省电模式，成功 2/2`

## 使用步骤

### 基本使用流程

#### 1. 切换到省电模式
```
1. 打开节能窗口
2. 点击"省电模式"按钮
3. 系统会记录当前的原始亮度
4. 所有显示器的亮度将降低到预设值
5. 状态栏将显示"已切换到省电模式，成功 X/Y"
```

#### 2. 恢复到正常模式
```
1. 点击"正常模式"按钮
2. 系统将恢复到之前记录的原始亮度值
3. 状态栏将显示"已恢复正常模式，成功 X/Y"
```

### 高级使用 - 自定义显示器配置

#### 为特定显示器设置不同的省电亮度
```
1. 在显示器卡片中，勾选"启用覆盖"
2. 使用亮度滑块设置该显示器的目标亮度
3. （可选）点击"应用自定义亮度"按钮立即应用
4. 之后切换到省电模式时，该显示器将使用此自定义亮度
```

#### 修改全局默认省电亮度
```
1. 在"默认省电亮度"区域调整滑块
2. 此操作会立即同步到所有未单独配置的显示器
3. 对所有未启用覆盖的显示器生效
```

## 常见问题

### 1. 显示器不在列表中
**症状**：扫描后列表为空或某些显示器不显示

**可能原因**：
- 显示器不支持 DDC/CI 协议
- 显示器连接线接触不良
- 显示驱动程序不完整
- 显示器已禁用在系统中

**解决方案**：
- 尝试更新显示驱动程序
- 点击"刷新"按钮重新扫描
- 检查物理连接
- 在系统显示设置中确认显示器已启用

### 2. 修改亮度无效
**症状**：点击"省电模式"或"正常模式"后，显示器亮度未改变

**可能原因**：
- 显示器不支持 DDC/CI
- 监视器的 OSD 菜单中禁用了亮度控制
- DDC/CI 通信失败

**解决方案**：
- 进入显示器 OSD 菜单（通常是显示器面板上的按钮）
- 查找"OSD 锁定"、"DDC/CI"或"USB 控制"选项
- 确保这些选项已启用
- 检查日志文件查看具体错误信息（详见"日志文件"部分）

### 3. 点击"正常模式"无法恢复亮度
**症状**：在应用了省电模式后，点击"正常模式"按钮，亮度没有返回原值

**可能原因**：
- 在应用省电模式前显示器已离线
- 硬件响应超时
- 基线亮度记录失败

**解决方案**：
1. 查看状态栏中的错误信息
2. 检查日志文件中的详细错误（见"日志文件"部分）
3. 尝试手动调整亮度然后再次应用模式
4. 重启程序并重新尝试

### 4. 窗口关闭后重新打开报错
**症状**：`System.InvalidOperationException` - "关闭窗口后，无法设置可见性"

**原因**：WPF 中已关闭的窗口无法重新打开

**解决方案**：
- 已在代码中修复，程序会自动检测并重建窗口
- 如仍遇到此问题，请重启 DaemonKit

## 日志文件

所有节能操作都会被记录到日志文件中，便于故障诊断。

**日志位置**：
```
%APPDATA%\DaemonKit\Logs\DaemonKit.log
```
或
```
<DaemonKit 运行目录>\Logs\DaemonKit.log
```

**日志示例**：
```
[PowerSaving] 开始应用省电模式...
[PowerSaving] 设置显示器覆盖: ASUS ProArt PA247CV = 40%
[PowerSaving] 应用成功: ASUS ProArt PA247CV
[PowerSaving] 开始恢复正常模式...
[PowerSaving] 恢复成功: ASUS ProArt PA247CV
```

**重要日志关键词**：
- `[PowerSaving]` - 节能窗口相关操作
- `[DDC/CI]` - 显示器硬件通信日志
- `成功` - 操作成功
- `失败` - 操作失败（需要关注错误详情）

## 技术细节

### 架构组件

1. **PowerSavingManager**
   - 高级接口，管理整个省电流程
   - 记录基线亮度用于恢复
   - 应用省电配置文件

2. **BrightnessCoordinator**
   - 协调多个亮度驱动程序
   - 发现显示设备
   - 路由亮度读写操作

3. **DdcCiBrightnessDriver**
   - 实现 DDC/CI 协议
   - 与硬件通信
   - 支持 Windows DisplayAPI

4. **PowerSavingViewModel**
   - 提供 MVVM 绑定
   - 处理 UI 事件
   - 同步显示器状态

### 支持的显示器类型

- DDC/CI 兼容的 LCD/LED 显示器
- HDMI/DisplayPort 连接的显示器
- USB-C 显示器（若支持 DDC/CI）

### 不支持的显示器类型

- 不支持 DDC/CI 的旧显示器
- USB 集线器连接的显示器
- 虚拟显示器 (Spacedesk, VB-Audio 等)

## 故障诊断

### 启用详细日志

1. 打开 `%APPDATA%\DaemonKit\` 目录
2. 查看 `DaemonKit.log` 文件
3. 搜索含有 `[PowerSaving]` 或 `[DDC/CI]` 的行

### 常见错误代码

| 错误信息 | 原因 | 解决方案 |
|---------|------|--------|
| "未记录基线亮度" | 在应用前显示器离线 | 确保显示器在应用省电前已连接 |
| "DDC/CI 调节失败" | 硬件通信失败 | 检查 OSD 菜单，启用 DDC/CI |
| "无法打开物理监视器" | 驱动程序问题 | 更新显示驱动程序 |
| "恢复亮度失败" | 无法恢复到原值 | 查看日志，尝试手动恢复 |

## 性能建议

- **显示器数量**：支持最多 10-16 个显示器（取决于系统）
- **切换延迟**：通常 500ms-2s（DDC/CI 通信延迟）
- **功耗节省**：一般可节省 15-30% 的显示器功耗
