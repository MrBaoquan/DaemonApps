## 系统概述

LicHper 的授权系统是一个跨 C++ 和 C# 的混合授权框架，用于验证和管理软件许可证。该系统支持：

- **机器码绑定**：通过 BIOS UUID 识别唯一机器
- **过期时间控制**：软件许可证可设置过期时间，过期后显示水印
- **缓存机制**：本地缓存授权令牌，支持离线使用
- **灵活续订**：支持续订、退订、清空等操作
- **加密存储**：使用 AES-256 加密本地授权数据

## 数据结构

### 1. License 结构体

存储整个机器的授权数据。

```cpp
struct License {
    // 机器序列号（BIOS UUID）
    std::string serial_number;
    
    // 应用授权映射表 {AppID -> LicenseInfo}
    std::map<std::string, LicenseInfo> data;
    
    // 缓存的用户登录令牌（加密）
    std::string cached_license;
    
    // 缓存令牌的过期时间
    std::string license_expired_at;
};
```

**序列化方式**：使用 cereal 库以 JSON 格式序列化，然后用 AES 加密

---

### 2. LicenseInfo 结构体

单个应用的授权信息。

```cpp
struct LicenseInfo {
    // 授权者用户名
    std::string username;
    
    // 授权更新时间
    std::string updated_at;
    
    // 授权过期时间（"1970-01-01 00:00:00" = 无许可证）
    std::string expired_at;
    
    // 最后验证的有效系统时间
    std::string last_verified_at;
    
    // 应用 ID
    std::string appid;
};
```

**时间格式**：`YYYY-MM-DD HH:MM:SS`

**特殊值**：
- `expired_at = "1970-01-01 00:00:00"` → 无授权状态
- `last_verified_at` → 防止系统时间篡改的关键

## 加密机制

### AES-256-CBC 加密

**密钥**：
```
"mrbaoquan1231231"（16 字符，用于 AES-128，不是真正的 AES-256）
```

> ⚠️ 注意：虽然代码注释提到 AES-256，但实际使用 16 字符密钥（128 位）

**初始化向量 (IV)**：
- 使用密钥作为 IV（非标准做法，应该使用随机 IV）

**编码方式**：
- 加密后使用 Base64 编码存储

### C++ 加密实现

```cpp
std::string AESEncrypt(const std::string& plaintext, const std::string& key) {
    std::string ciphertext;
    CBC_Mode<AES>::Encryption encryption((byte*)key.c_str(), key.length(), 
                                         (byte*)key.c_str());
    StringSource(plaintext, true, 
                 new StreamTransformationFilter(encryption, 
                 new Base64Encoder(new StringSink(ciphertext))));
    return ciphertext;
}
```

### C# 加密实现

```csharp
public static string AESEncrypt(string plaintext, byte[] key) {
    using (AesCryptoServiceProvider aes = new AesCryptoServiceProvider()) {
        aes.Key = key;
        aes.IV = key;  // 同样使用密钥作为 IV
        aes.Mode = CipherMode.CBC;
        
        ICryptoTransform encryptor = aes.CreateEncryptor(aes.Key, aes.IV);
        byte[] encrypted = encryptor.TransformFinalBlock(
            Encoding.UTF8.GetBytes(plaintext), 0, plaintext.Length);
        return Convert.ToBase64String(encrypted);
    }
}
```

## 工作流程

### 1. 系统初始化

```
启动应用
    ↓
调用 Validate(AppID)
    ↓
加载授权文件 (~\.authrc)
    ├─ 如果不存在：创建新授权文件
    │   ├─ 获取 BIOS UUID 作为 serial_number
    │   └─ 初始化为无授权状态
    └─ 如果存在：解密并加载
        ├─ AES 解密
        └─ cereal 反序列化
    ↓
机器码验证
    ├─ 对比 serial_number 与当前 BIOS UUID
    ├─ 不匹配 → 返回 10001，显示水印
    └─ 匹配 → 继续
    ↓
查询应用授权
    ├─ 获取 LicenseInfo[AppID]
    ├─ 如果不存在 → 创建默认（无授权）
    └─ 检查过期时间
        ├─ 已过期或无授权 → 返回 10002，显示水印
        └─ 有效 → 更新验证时间，保存，返回 0
```

### 2. 用户登录流程

```
用户输入许可证令牌
    ↓
ParseLicense(userLicense)
    ├─ AES 解密许可证
    ├─ JSON 反序列化
    └─ 返回 UserInfo（包含用户名、过期时间等）
    ↓
验证令牌有效性
    ├─ error 字段为空 → 令牌有效
    └─ 其他字段不为空 → 令牌有效
    ↓
缓存令牌
    ├─ 保存到 License.cached_license
    ├─ 设置过期时间（今天 23:59:59）
    └─ 加密保存到 ~\.authrc
    ↓
更新应用授权 (RenewByLicense)
    ├─ 验证令牌的 AppID 与当前应用匹配
    ├─ 更新 LicenseInfo[AppID]
    │   ├─ username = 来自令牌
    │   ├─ expired_at = 来自令牌
    │   └─ last_verified_at = 当前时间或缓存的更晚时间
    └─ 重新调用 Validate 验证授权
```

### 3. 许可证续订流程

```
用户点击"续订"按钮
    ↓
Renew(AppID, expiredAt)
    ├─ 检查登录状态 (checkLogin)
    │   ├─ 缓存令牌存在且未过期
    │   └─ 令牌有效
    ├─ 获取登录用户信息
    ├─ 更新 LicenseInfo[AppID]
    │   ├─ username 保持不变
    │   └─ expired_at = 新的过期时间
    └─ 保存并返回 0
```

### 4. 离线缓存验证

```
离线使用流程：
    ↓
Validate(AppID) 调用
    ↓
检查许可证
    ├─ 机器码 ✓
    ├─ 授权有效期 ✓
    └─ 可离线使用
    ↓
注：无需网络连接，使用本地加密授权数据
```

## API 接口

### C++ 接口 (validator.h)

所有接口均导出为 COM BSTR 返回值，支持跨 DLL 边界调用。

#### 1. Login - 用户登录

```cpp
BSTR __stdcall Login(BSTR userLicense);
```

**参数**：
- `userLicense` - 许可证令牌（AES 加密的 JSON）
  - 为空时尝试使用缓存令牌

**返回值**：
- JSON 字符串：`{"value0": {UserInfo}}`
- 失败：`{"value0": {"error":"无效许可证"}}`

**逻辑**：
1. 如果 `userLicense` 为空，尝试加载缓存登录
2. 验证缓存令牌未过期
3. 解析和验证许可证格式
4. 缓存令牌到本地文件
5. 返回用户信息

**示例** (C#)：
```csharp
var userLicense = "Base64EncodedAESData...";
var result = LicHperInterface.Login(userLicense);
// 返回: {"value0": {"username":"John","appid":"MyApp",...}}
```

---

#### 2. Logout - 用户退出

```cpp
int __stdcall Logout();
```

**返回值**：
- `0` - 成功

**逻辑**：
1. 清空缓存的许可证令牌
2. 将缓存过期时间设为 `"1970-01-01 00:00:00"`
3. 保存修改

---

#### 3. Validate - 验证授权

```cpp
int __stdcall Validate(BSTR AppID, int uiFlag = 0);
```

**参数**：
- `AppID` - 应用 ID（如 `"MyApp"`, `"Daemon"` 等）
- `uiFlag` - UI 标志
  - `0` - 授权无效时显示水印（默认）
  - 非 0 - 仅验证，不显示水印

**返回值**：
- `0` - 授权有效，软件可正常运行
- `10001` - 机器码不匹配
- `10002` - 无授权或已过期

**逻辑**：
1. 加载本地授权文件
2. 获取 BIOS UUID（机器码）
3. 验证机器码是否匹配
4. 查询该应用的授权信息
5. 检查过期时间
6. 如果授权无效且 `uiFlag=0`，在独立线程中运行水印渲染
7. 更新最后验证时间并保存

**示例** (C#)：
```csharp
int result = LicHperInterface.Validate("MyApp", 0);
if (result == 0) {
    // 授权有效
} else if (result == 10002) {
    // 无授权或已过期，水印已显示
}
```


## 错误处理

## 安全考虑

### ⚠️ 安全问题

1. **固定加密密钥**
   - 密钥 `"mrbaoquan1231231"` 内置在代码中
   - **风险**：任何人可反编译提取密钥
   - **建议**：使用动态密钥或密钥管理服务

2. **IV 与密钥相同**
   - 非标准做法
   - **建议**：使用随机 IV

3. **时间戳验证** ✓ 有效
   - `last_verified_at` 防止系统时间倒回
   - 超前的时间戳会成为新的参考点

4. **缓存令牌管理**
   - 缓存在本地文件中
   - 过期时间为每天 23:59:59
   - 允许离线使用但有风险

### 安全建议

1. **增强密钥管理**
   ```cpp
   // 使用环境变量或配置文件
   std::string key = std::getenv("LICENSE_KEY");
   if (key.empty()) {
       // 使用默认密钥（仅开发环境）
   }
   ```

2. **添加令牌签名**
   ```cpp
   // HMAC-SHA256 签名验证
   // 确保令牌未被篡改
   ```

3. **机器码多维度**
   ```cpp
   // 不仅使用 BIOS UUID，还包括
   // - 硬盘序列号
   // - MAC 地址
   // - CPU ID
   ```

4. **网络验证**
   - 定期与服务器验证（如果需要）
   - 支持离线但有时间限制

## 时间验证机制

### 防止系统时间篡改

```
核心原理：
- 存储 last_verified_at = 最后验证时的系统时间
- 下次验证时，如果系统时间 < last_verified_at
  → 使用 last_verified_at 作为新的参考时间
  → 防止用户修改系统时间来延长许可证有效期
```

**实现**：
```cpp
std::string latestSystime(std::string lastVerifiedTime) {
    auto _now = std::chrono::system_clock::now();
    auto _last = string_to_time(lastVerifiedTime);
    
    // 如果缓存时间比当前时间更晚，使用缓存时间
    if (_last > _now) {
        return time_to_string(_last);
    }
    return time_to_string(_now);
}
```

## 故障排查

### 常见问题

**Q1: 许可证无法激活**
- 检查许可证格式是否正确（需要完整的加密 Base64 字符串）
- 验证 AppID 是否匹配
- 查看 error 字段是否有具体错误信息

**Q2: 机器码不匹配错误**
- 检查是否在虚拟机中运行（BIOS UUID 可能不稳定）
- 查看 `GetBiosUUID()` 获取的值是否一致
- 考虑在许可证中记录创建时的 UUID

**Q3: 水印不显示**
- 验证 `uiFlag` 参数是否为 0
- 检查 DirectX 环境是否正确配置
- 查看日志是否有渲染错误

**Q4: 缓存过期问题**
- 本地缓存每天重置（每天 23:59:59 过期）
